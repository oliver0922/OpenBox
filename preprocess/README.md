# Dataset Preparation & Context-aware Refinement

This folder contains the full data-generation pipeline of OpenBox for the
Waymo Open Dataset. Running steps 0–6 below turns raw Waymo TFRecords into
the per-scene inputs that the box-generation stage consumes: camera-aligned
point clouds, cross-camera instance point clouds (context-aware refined), and
a static-background TSDF mesh.

```
[0] waymo_processed_gen ──► $OUT/processed   (lidar frames, camera-visible subset, poses, fov infos; steps 4-6 + box generation)
[1] waymo_file_gen ──────► $OUT/scenes      (points / projections / images / masks / poses)
        │
        ├──► [2] gen_multicam_samv2 ──► [3] merge_instances ──► [4] refine_sam_pcd
        │        $OUT/sam (2D masks → 3D)    $OUT/sam (cross-camera IDs)  $OUT/refined
        │
        └──► [5] compute_ppscore ──► [6] dynamic_removed_vdbfusion
                 $OUT/ppscore            $OUT/mesh (static background mesh)
```

Every step takes explicit input/output paths, and every output lands under a
single root `$OUT` in the layout shown in [Output layout](#output-layout).
Step 3 is the one step that writes back into its input tree (`$OUT/sam`).
`scene-N` always corresponds to line N (0-based) of `ImageSets/train.txt`.
Steps 0 and 1 are independent of each other and can run concurrently.

## Environment

Everything runs in a single conda environment. **Install order matters**
(torch → mmcv → pinned requirements): mmcv must already be present before the
requirements file is installed, and the requirements file must be installed
with `--no-deps` — see the notes inline.

```bash
conda create -n openbox python=3.10.15 -y
conda activate openbox

# 1. PyTorch (pinned — step 2 output changes with a different torch/mmcv pair)
pip install torch==2.3.1 torchvision==0.18.1 torchaudio==2.3.1 \
    --index-url https://download.pytorch.org/whl/cu121

# 2. mmcv 2.1.0 — must be BUILT FROM SOURCE against torch 2.3.1. No
#    compatible binary wheel exists anywhere: PyPI ships only the sdist, the
#    OpenMMLab cu121/torch2.3 index starts at 2.2.0, and the cu121/torch2.1
#    wheel fails at import under torch 2.3 (undefined symbol — ABI change).
#    The build needs a CUDA 12.1 nvcc (CUDA_HOME) and setuptools<81 (newer
#    setuptools removed pkg_resources, which mmcv's setup.py imports).
pip install "setuptools==60.2.0" wheel ninja
CUDA_HOME=<cuda-12.1-toolkit> FORCE_CUDA=1 MMCV_WITH_OPS=1 MAX_JOBS=32 \
    pip install mmcv==2.1.0 --no-build-isolation --no-binary mmcv
python -c "from mmcv.ops import nms"    # check that the CUDA ops import

# 3. Grounding DINO + SAM2 stack (rest of the setup: Grounded-SAM-2/README.md).
#    The requirements file is a complete pip freeze — install it with
#    --no-deps and without the mmcv line (built above); a plain resolver pass
#    backtracks into re-building the mmcv sdist and the whole install fails.
grep -v '^mmcv==' ../Grounded-SAM-2/requirements_groundedsam.txt > /tmp/req.txt
pip install --no-deps -r /tmp/req.txt
pip install --no-deps --no-build-isolation -e <your mmdetection fork>

# 4. CPU stages
pip install open3d==0.19.0 scipy==1.15.2 scikit-learn==1.5.0 \
    hdbscan==0.8.40 vdbfusion==0.1.6 faiss-cpu==1.7.4
pip install ../patchwork-plusplus/python

# 5. Waymo parsing on python 3.10 (TF is only used to read TFRecords)
pip install --no-deps waymo-open-dataset-tf-2-12-0==1.6.4
pip install tensorflow-cpu==2.15.1
# waymo-open-dataset predates protobuf 4; patch its parser calls once:
sed -i 's/bytearray(/bytes(/g' \
    "$(python -c 'import waymo_open_dataset.utils.frame_utils as m; print(m.__file__)')"
```

No CUDA 12.1 toolkit on the system? Install one into its own conda prefix
and point `CUDA_HOME` at it — it is needed only for this one build:

```bash
conda create -y -p <prefix>/cuda121 -c nvidia/label/cuda-12.1.1 cuda-toolkit
```

Step 2 additionally needs the mmdetection v3.3 fork with
`Grounded-SAM-2/parent_files/` applied and the two checkpoints
(`sam2_hiera_large.pt`, and `groundingdinofintune.pth` which the step-2 script
auto-downloads from Hugging Face) — follow
[`Grounded-SAM-2/README.md`](../Grounded-SAM-2/README.md) once; every other
step is a plain script call.

## Required data

| data | layout | source |
|---|---|---|
| Waymo TFRecords | `$WAYMO/train/segment-*.tfrecord` (798 training segments) | [Waymo Open Dataset](https://waymo.com/open/) v1.x perception |
| Split file | `$WAYMO/ImageSets/train.txt` — line N is the segment name of `scene-N` | included in this repo (`data/waymo/ImageSets/train.txt`) |
| Detector / SAM2 checkpoints | `groundingdinofintune.pth` (Grounding DINO swin-b, auto-downloaded from [HF `oliver0922/GroundingDINOfintune`](https://huggingface.co/oliver0922/GroundingDINOfintune)), `sam2_hiera_large.pt` | see `Grounded-SAM-2/README.md` |

Everything else is generated by the pipeline itself.

## Output layout

After steps 0–6, `$OUT` looks like this (`N` = scene index, `NNNN`/`NNNNNN` =
zero-padded frame index, `<segment>` = TFRecord name without `.tfrecord`,
`<CAM>` ∈ FRONT, FRONT_LEFT, FRONT_RIGHT, SIDE_LEFT, SIDE_RIGHT,
`<aug>` ∈ `no_aug`, `adaptive1200_30_50_10_2`):

```
$OUT/
├── processed/<segment>/                        # step 0 — OpenPCDet layout
│   ├── NNNN.npy                                #   float32 (N,6) x,y,z,intensity,elongation,NLZ (vehicle frame)
│   ├── masked_points/NNNN.npy                  #   the rows of NNNN.npy that project into a camera image
│   ├── <segment>.pkl                           #   list of {frame_id, pose(float32 4x4)}
│   └── <segment>_fov.pkl                       #   per-frame OpenPCDet infos (meta, pose, GT boxes with x>0,
│                                               #   masked per-lidar counts); box generation copies its frame records
├── scenes/scene-N/                             # step 1
│   ├── pointcloud/NNNNNN.bin                   #   float32 (P,3)
│   ├── pointcloud_projection/NNNNNN.bin        #   int32 (P,6): (cam,u,v) for up to two cameras
│   ├── annotations/NNNNNN.bin                  #   float64 (B,7) GT boxes
│   ├── pose/NNNNNN.bin                         #   float64 (4,4) ego pose
│   └── <CAM>/
│       ├── image/NNNNNN.jpeg                   #   1920x1280 (FRONT*), 1920x886 (SIDE*)
│       ├── mask_1/NNNNNN.bin                   #   int64 indices of points whose 1st projection is <CAM>
│       ├── mask_2/NNNNNN.bin                   #   int64 indices of points whose 2nd projection is <CAM>
│       ├── intrinsic/NNNNNN.bin                #   float64 (9,) waymo camera intrinsic vector
│       └── projection_mat/NNNNNN.bin           #   float64 (4,4) scene frame -> this frame's camera
├── sam/scene-N/                                # steps 2–3
│   ├── <CAM>/
│   │   ├── erosion/mask_data/mask_NNNNNN.npy   #   uint16 (H,W) instance masks, 0 = background
│   │   ├── erosion/json_data/mask_NNNNNN.json  #   instance id / class / box per frame
│   │   ├── erosion/result/, result/, adaptive_erosion/1200_30_50_10_2/result/   # annotated previews
│   │   ├── visualization/uppc_continuous_sam/NNNNNN.bin          # float32 (M,4) x,y,z,instance_id
│   │   ├── visualization/uppc_color_continuous_sam/NNNNNN.bin    # float32 (M,3) rgb
│   │   └── adaptive1200_30_50_10_2/visualization/...             # same two dirs, adaptive-eroded masks
│   ├── instance_classname_dict.pkl             #   {instance_id: class_name}
│   ├── merged_sam_pc/<aug>/NNNNNN.bin          # step 3 — float32 (M,4), ids merged across cameras
│   ├── merged_sam_color/<aug>/NNNNNN.bin       #          float32 (M,3)
│   ├── conn_dict_<aug>.pkl                     #          {instance_id: merged_into_id}
│   └── agg_mask.json                           #          per-frame 2D boxes per merged instance (adaptive run)
├── refined/scene-N/refined_sam_pc/<aug>/NNNNNN.bin   # step 4 — float64 (R,4) x,y,z,instance_id
├── ppscore/<segment>/ppscore/NNNN.npy          # step 5 — float16 (N,) persistence score per lidar point
└── mesh/scene-N/                               # step 6
    ├── static_vert0.15_0.4.bin                 #   float64 (V,3)
    └── static_tri0.15_0.4.bin                  #   int32 (T,3)
```

## Pipeline

All commands below use two variables:

```bash
WAYMO=/path/to/waymo          # $WAYMO/train/*.tfrecord + $WAYMO/ImageSets/train.txt
OUT=/path/to/openbox_data     # every step writes under here (see Output layout)
```

Scene ranges are inclusive in every step (`--scene-end 797` = all 798 scenes).

### 0. Processed lidar frames + poses — `waymo_processed_gen.py`

Extracts every frame's lidar points in the standard OpenPCDet layout
(float32 `(N, 6)`: x, y, z, intensity, elongation, NLZ flag) together with a
per-segment pose pkl, and two files the box-generation stage needs:
`masked_points/NNNN.npy`, the rows of `NNNN.npy` whose lidar return projects
into one of the five camera images (Waymo's per-return camera projection,
first slot set; the label point counts are taken on this subset), and
`<segment>_fov.pkl`, the per-frame OpenPCDet info records (frame id, context
name and timestamp, camera image shapes, float32 ego pose, the GT boxes in
front of the vehicle — centre x > 0 — and the masked per-lidar point counts);
stage 2 of the box generation copies these records and replaces their
`annos` with the pseudo labels. Steps 4–6 read only `NNNN.npy` and the pose
pkl; steps 1–3 need nothing from here. CPU only, one process per scene.

```bash
python waymo_processed_gen.py \
    --waymo-root $WAYMO --out-root $OUT/processed \
    --scene-start 0 --scene-end 797 --workers 16
```

**Already ran OpenPCDet's `create_waymo_infos` (e.g. for training)?** Steps
4–6 can read that root instead of `$OUT/processed` (`<segment>/NNNN.npy` is
the same file, and its `<segment>.pkl` carries identical pose entries), but
the box-generation stage also needs `masked_points/` and `<segment>_fov.pkl`,
which OpenPCDet does not write — so run this step anyway, into its own root.
**If you run both, keep the two outputs in separate roots.** Both
preprocessings write `<segment>/<segment>.pkl`, but OpenPCDet's pkl also
carries the annotations and point counts training needs, while this script's
is pose-only — and OpenPCDet run afterwards skips any segment whose pkl
already exists. The script refuses to overwrite a pkl that carries more than
`{frame_id, pose}`, so pointing `--out-root` at an OpenPCDet root fails fast
instead of silently destroying it.

### 1. Per-scene data — `waymo_file_gen.py`

Parses every TFRecord frame and writes the per-scene tree all later steps
share: the full point cloud (both lidar returns, all 5 lidars), its camera
projections, per-camera point-index masks, GT boxes, ego poses, the five
camera JPEGs, and each camera's calibration (`intrinsic/` — the waymo
9-vector; `projection_mat/` — scene frame, i.e. the ego pose of frame 0, to
that frame's camera: `inv(pose_f @ extrinsic) @ pose_0`). The box-generation
stage consumes the calibration files for its 2D IoU vote. CPU by default (`--device gpu` is faster but shifts point
coordinates by up to ~5 mm).

```bash
python waymo_file_gen.py \
    --waymo-root $WAYMO --output-root $OUT/scenes \
    --scene-start 0 --scene-end 797 --workers 16
```

### 2. 2D instance masks, lifted to 3D — `gen_multicam_samv2_data_unified.py`

Runs Grounding DINO detection + SAM2 mask tracking over all five cameras
(instance ids stay unique across cameras within a scene), then unprojects
every mask onto the lidar points. One worker per GPU; ~32 GB VRAM each.
Run it from the mmdetection fork root (setup: `Grounded-SAM-2/README.md`);
both checkpoints are downloaded on first run (detector from Hugging Face,
SAM2 from the official release). The HF repo is gated with auto-approval:
run `huggingface-cli login` once and accept access on the model page.

```bash
python groundedsamv2/gen_multicam_samv2_data_unified.py \
    configs/grounding_dino/grounding_dino_swin-b_finetune_8xb4_1x_nus.py \
    --data_dir $OUT/scenes --out_dir $OUT/sam \
    --scene-start 0 --scene-end 797 --gpus 0,1,2,3
```

- **Input** — `$OUT/scenes` (`<CAM>/image`, `pointcloud`, `pointcloud_projection`)
- **Output** — `$OUT/sam/scene-N/<CAM>/...`, `instance_classname_dict.pkl`

### 3. Cross-camera instance merging — `merge_instances.py`

Links instance ids that share duplicated 3D points across cameras (the same
physical object seen by two cameras) and rewrites the five per-camera instance
clouds into one merged per-frame cloud. Run once per mask variant
(`no_aug`, `adaptive1200_30_50_10_2`). Writes into `$OUT/sam` itself.

```bash
for AUG in no_aug adaptive1200_30_50_10_2; do
python merge_instances.py \
    --data_root $OUT/sam --augname $AUG \
    --scene-start 0 --scene-end 797 --num_workers 32
done
```

- **Input** — `$OUT/sam/scene-N/<CAM>/[<aug>/]visualization/uppc_*_sam` (+ step-2 `erosion/json_data` for the box aggregate)
- **Output** — `$OUT/sam/scene-N/{merged_sam_pc,merged_sam_color}/<aug>/`, `conn_dict_<aug>.pkl`; the
  `adaptive1200_30_50_10_2` run also writes `agg_mask.json` (per-frame 2D detection boxes keyed by
  merged instance id — the box-generation stage reads it for the 2D IoU vote)

### 4. Context-aware refinement — `refine_sam_pcd.py`

Cleans the merged instance clouds against the raw lidar: Patchwork++ ground
removal, HDBSCAN clustering of the remaining points, and majority-vote
matching of each geometric cluster to a merged instance — removing the noisy
points that 2D-to-3D projection introduces.

```bash
python refine_sam_pcd.py \
    --seq_data_dir $OUT/processed --sam_data_dir $OUT/sam \
    --split_file $WAYMO/ImageSets/train.txt \
    --aug_name adaptive1200_30_50_10_2 \
    --scene-start 0 --scene-end 797 --out_dir $OUT/refined --num_workers 16
```

- **Input** — `$OUT/sam/scene-N/merged_sam_pc/<aug>/`, `$OUT/processed/<segment>/NNNN.npy`
- **Output** — `$OUT/refined/scene-N/refined_sam_pc/<aug>/NNNNNN.bin`

### 5. Persistence score — `compute_ppscore.py`

Scores every lidar point by how persistently it is observed across a ±30-frame
temporal window (normalized neighbor-count entropy, float16). High score =
static structure; step 6 thresholds at 0.7.

```bash
python compute_ppscore.py \
    --processed-data-root $OUT/processed \
    --split-file $WAYMO/ImageSets/train.txt \
    --scene-start 0 --scene-end 797 --out-root $OUT/ppscore --num-workers 10
```

- **Input** — `$OUT/processed/<segment>/{NNNN.npy, <segment>.pkl}`
- **Output** — `$OUT/ppscore/<segment>/ppscore/NNNN.npy`

### 6. Static background mesh — `dynamic_removed_vdbfusion.py`

Fuses the static points (persistence score > 0.7) of every frame into a
scene-level TSDF volume (0.15 m voxels) and extracts a triangle mesh — the
dynamic-object-free background used as an SDF reference for box generation.

```bash
python dynamic_removed_vdbfusion.py \
    --scene-data-root $OUT/scenes --processed-data-root $OUT/processed \
    --ppscore-root $OUT/ppscore \
    --split-file $WAYMO/ImageSets/train.txt \
    --scene-start 0 --scene-end 797 --out-root $OUT/mesh
```

- **Input** — `$OUT/scenes/scene-N/pose/`, `$OUT/ppscore/`, `$OUT/processed/<segment>/NNNN.npy`
- **Output** — `$OUT/mesh/scene-N/static_vert0.15_0.4.bin`, `static_tri0.15_0.4.bin`
